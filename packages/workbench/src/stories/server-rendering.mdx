# Server rendering

The components can be rendered to HTML on a server with [Lit SSR](https://lit.dev/docs/ssr/overview/). The page then paints styled components before any script runs, which helps a slow connection and anything that reads the HTML. When the components' definitions load in the browser, each one either **replaces** the server's markup with its own render (the default) or **hydrates** it: keeps it and attaches to it (opt-in).

`npm run check:consumer` renders every component on a server from the packed package and checks both ways of loading it in a browser, so what this page says is tested.

## Install

```sh
npm install @dieselpunk/core @lit-labs/ssr
# Only to hydrate:
npm install @lit-labs/ssr-client
```

Core has no dependency on either Lit SSR package. Install the major version of `@lit-labs/ssr` that matches Lit 3.

## On the server

Import the `register.js` entries the page uses, then render the page with `@lit-labs/ssr`. Each component's shadow tree is written as a declarative shadow root, which browsers attach while they parse the page.

```ts
// server.ts
import '@dieselpunk/core/panel/register.js';
import '@dieselpunk/core/button/register.js';
import { html, renderThunked } from '@lit-labs/ssr';
import { RenderResultReadable } from '@lit-labs/ssr/lib/render-result-readable.js';

const page = html`<!doctype html>
  <html lang="en">
    <head>
      <link rel="stylesheet" href="/tokens.css" />
      <script type="module" src="/client.js"></script>
    </head>
    <body>
      <punk-panel>
        <span slot="header">Assembler</span>
        <punk-button>Craft</punk-button>
      </punk-panel>
    </body>
  </html>`;

// Streams the page as it renders; any framework that accepts a Node stream works.
response.body = new RenderResultReadable(renderThunked(page));
```

- **No setup.** The components need no `LitElementRenderer` options; they render with Lit SSR's defaults.
- **Stylesheets.** Link `tokens.css` and `themes.css` as in a client-only page. Their custom properties reach the declarative shadow roots like any other.
- **Built-in text** is in the server's Lit Localize locale: English, unless the server configures one. The locale is shared by every request, so a server renders one language at a time.

## In the browser: replace

Import the same `register.js` entries. When each definition loads, the component replaces the server's markup with its own render, in the same task, so no frame paints in between.

```js
// client.js
import '@dieselpunk/core/panel/register.js';
import '@dieselpunk/core/button/register.js';
```

This is the default, and it needs nothing from Lit SSR in the browser. Loading Lit's hydration support for your own components does not change it.

## In the browser: hydrate

To keep the server's markup and attach to it instead, import Lit's hydration support and then `@dieselpunk/core/hydrate.js`, before any component:

```js
// client.js
import '@lit-labs/ssr-client/lit-element-hydrate-support.js';
import '@dieselpunk/core/hydrate.js';
import '@dieselpunk/core/panel/register.js';
import '@dieselpunk/core/button/register.js';
```

Hydration keeps the nodes the user already sees, so nothing is rebuilt and focus stays where it is. Each component first renders exactly what the server rendered, then updates once for what the server could not know (below). `hydrate.js` is about 0.55 kB, and only pages that import it pay for it.

Built-in text hydrates correctly when the page uses the server's locale at that moment. If it does not, the server's words stay until the locale changes.

## What the first paint cannot know

The server has no page around each component, so the first paint can differ from what follows the upgrade:

| What                                        | First paint                                   | After the upgrade            |
| ------------------------------------------- | --------------------------------------------- | ---------------------------- |
| Language for numbers                        | The component's own `lang`, else English      | The nearest `lang`           |
| Direction read in script                    | The component's own `dir`, else left to right | The element's direction      |
| Children: options, items, counts            | None. Slotted content still shows             | Read from the children       |
| Optional strips, such as a panel's header   | Hidden                                        | Shown when they have content |
| Roles and states written on the host        | Not written                                   | Written                      |
| Overlays with `open`                        | Closed                                        | Open                         |
| Sizes, a toolbar's overflow, a menu's place | Before layout                                 | Measured                     |

Layout from CSS, including `:dir()` and logical properties, is right from the start. To make the first paint match where the page's language or direction is not English and left to right, set `lang` and `dir` on the components themselves.

## Before the definitions load

The server's HTML is static until then. Slotted links work, and a field can take focus and typed text, which the upgrade keeps, with no `input` or `change` event.

A form submitted before its controls load does not include their values, since an undefined element is not a form control yet. Enable the submit button once the definitions have loaded, or use native controls where the form must work without script.

## Cost

Lit SSR writes a component's styles into every instance, and styles are most of each instance's bytes: one slot is about 6 kB of HTML. Compression absorbs the repetition, so 100 slots are about 634 kB raw and about 7 kB gzipped. Serve pages compressed, and render long collections in the browser.
