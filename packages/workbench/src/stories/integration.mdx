# Integration

`@dieselpunk/core` is plain Web Components built with Lit. It needs no framework and no global setup beyond optional CSS imports.

## Install

```sh
npm install @dieselpunk/core
```

Lit and Lit Localize come with it. To translate the built-in text, also install `@dieselpunk/locales` (see the Localization guide):

```sh
npm install @dieselpunk/locales
```

The examples below assume a tool that resolves bare module specifiers, such as Vite or esbuild. To use the packages with no build step, see [Without a build step](#without-a-build-step).

## Register only what you use

Each component has two entries. The class entry has no side effects. The `register.js` entry defines the element.

```js
// Define only the elements this page uses.
import '@dieselpunk/core/button/register.js';
import '@dieselpunk/core/panel/register.js';
```

`@dieselpunk/core/icon-button/register.js` also registers `punk-tooltip`, because the icon button renders one.

## Plain HTML

```html
<link rel="stylesheet" href="/node_modules/@dieselpunk/core/dist/css/tokens.css" />
<link rel="stylesheet" href="/node_modules/@dieselpunk/core/dist/css/themes.css" />

<script type="module">
  import '@dieselpunk/core/panel/register.js';
  import '@dieselpunk/core/button/register.js';
</script>

<punk-panel>
  <span slot="header">Assembler</span>
  <punk-button variant="primary">Start</punk-button>
</punk-panel>
```

The stylesheets are optional. Without them every component renders in the default dark, compact appearance. Import `tokens.css` to let ancestors override tokens, and `themes.css` to use themes other than the default.

- `@dieselpunk/core/` maps the `register.js` entries. A class entry is at `/node_modules/@dieselpunk/core/dist/components/<name>/index.js`.
- `#dev` is the switch for development warnings. `dev.js` leaves them off; `dev.dev.js` turns them on.
- The Lit entries cover what Lit's own modules import. Add an entry for any other package a page imports.

## Theme and density

Set two attributes on `<html>` or on any element. They apply to everything inside it, and nested values override outer ones.

```html
<html data-punk-theme="light" data-punk-density="low"></html>
```

Themes are `dark` (default), `light`, `high-contrast`, `reduced-texture`, and `auto`, which follows the system color scheme. Densities are `compact` (default) and `low`.

## TypeScript

Import classes and types from the package root, or from a component entry.

```ts
import type { PunkButton, ButtonVariant } from '@dieselpunk/core';
import '@dieselpunk/core/button/register.js';

const button = document.querySelector('punk-button')!;
button.addEventListener('click', () => button.setAttribute('loading', ''));
```

Importing a class never registers its element. Register it with the matching `register.js` entry.

## Forms

`punk-button` is form-associated. Its `type` defaults to `button`, so set `type="submit"` or `type="reset"` explicitly. It submits the enclosing form without a submitter.

The checkbox, switch, slider, text field, number field, and select are form-associated too. Each submits its value under its `name`, takes `required` and `disabled` (a disabled `<fieldset>` around them also counts), puts its value back to what the markup wrote on a form reset, and has the native `validity`, `validationMessage`, `checkValidity()`, `reportValidity()`, and `setCustomValidity()`. A text field and a number field submit the text the user sees; a select submits the chosen option's `value`, and nothing while none is chosen.

```html
<form>
  <punk-text-field name="callsign" label="Callsign" required></punk-text-field>
  <punk-number-field name="thrust" label="Thrust" min="0" max="10"></punk-number-field>
  <punk-select name="squadron" label="Squadron">
    <option value="a">Alpha</option>
    <option value="b">Beta</option>
  </punk-select>
</form>
```

The fields send `input` while the user types or steps and `change` when a change is committed, on the host. A form control inside a shadow root is not filled by every password manager.

## Translating built-in text

Components contain a few built-in words, such as the loading announcement and the state words in an accessible name. They are written with [Lit Localize](https://lit.dev/docs/localization/overview/)'s `msg()`, so the page configures Lit Localize once and switches locales with `setLocale()`. Without that, the English text shows. Core and the page must use one copy of `@lit/localize`, since the configuration is module state.

```ts
import { configureLocalization, str } from '@lit/localize';

const { setLocale } = configureLocalization({
  sourceLocale: 'en',
  targetLocales: ['de'],
  loadLocale: async () => ({
    templates: {
      loading: 'Laden',
      // A message with values: each `${n}` is the position of a value in the English message.
      stackCapacity: str`${0} von ${1}`,
    },
  }),
});

await setLocale('de');
```

Mounted components re-render when the locale is ready. A message is found by its id:

| Id              | Default                                                         | Used by              |
| --------------- | --------------------------------------------------------------- | -------------------- |
| `loading`       | `Loading`                                                       | Button, icon button  |
| `invalid`       | `invalid`                                                       | Slot, item stack     |
| `stackCount`    | `${count}`                                                      | Item stack           |
| `stackCapacity` | `${count} of ${capacity}`                                       | Item stack           |
| `durability`    | `durability ${percent}`                                         | Item stack           |
| `quality`       | `quality ${level}`                                              | Item stack           |
| `unavailable`   | `unavailable`                                                   | Recipe               |
| `craftable`     | `can craft ${times}`                                            | Recipe               |
| `meterWarning`  | `warning`                                                       | Meter                |
| `meterCritical` | `critical`                                                      | Meter                |
| `invalidField`  | `invalid`                                                       | Text, number, select |
| `increase`      | `Increase`                                                      | Number field         |
| `decrease`      | `Decrease`                                                      | Number field         |
| `close`         | `Close`                                                         | Window               |
| `moveWindow`    | `Move window`                                                   | Window               |
| `moving`        | `Moving. Use the arrow keys, Enter to place, Escape to cancel.` | Window               |
| `dismiss`       | `Dismiss`                                                       | Toast                |
| `notifications` | `Notifications`                                                 | Toast stack          |

## Development warnings

The package logs warnings for misuse, such as an icon button with no `label`, when it is resolved with the `development` export condition (Vite does this in dev mode). Production builds drop them.
