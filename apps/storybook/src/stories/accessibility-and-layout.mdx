# Accessibility and layout

How the components behave at different text sizes, writing directions, and system settings. Each behavior below is covered by an automated test or a visual baseline.

## Reflow and zoom

Nothing forces horizontal scrolling at 200% zoom, down to a layout 187px wide (a 375px window at 200%).

- **Buttons** keep their height as a minimum and wrap a long label onto more lines. A one-line label is exactly the size it always was: 28, 36, and 44px at compact density for `sm`, `md`, and `lg`, and 34, 44, and 54px at low density. A button never grows wider than its container.
- **Icon buttons** stay square. Their content is an icon, not text.
- **Panels** and **dividers** wrap their text. A word too long for the line breaks only when it cannot fit on a line by itself.
- **Tooltips** are never wider than the viewport, whatever `--punk-tooltip-max-width` is.
- **Progress bars** wrap a long label above the track.
- **Slots** and **item stacks** keep their size, and a **slot grid** drops columns before it shrinks a slot, down to one column.
- **Recipes** grow with their content, a long name wraps, and the text moves under the icon when too little room is left beside it.
- **Meters** wrap a long label above the track, and a vertical meter keeps its length.
- **Status lights** wrap their text next to the shape.

Components set no widths of their own, so they fill the container you place them in. Put a button in a container that can shrink, such as a block container or a flex item with `min-inline-size: 0`, and it wraps.

## Right-to-left

Set `dir="rtl"` on `<html>` or any ancestor. Layout uses logical properties throughout, so no component needs a separate style:

- Headers, labels, and values swap sides, and the start and end icon slots of a button swap with them.
- Progress fills grow from the right. The indeterminate stripes scroll the same way in both directions, because they are decoration and not a measure.
- A tooltip with `placement="start"` opens on the right side of its anchor.
- A slot grid's horizontal arrow keys swap, so the arrow that points toward the start of the row moves to the next item. Home is the rightmost item of a row.
- Meter and recipe fills, and the arrow between a recipe's ingredients and products, flip.

## Forced colors

Under `forced-colors: active`, the gradients, textures, and bevels give way to plain borders in system colors. Information that normally depends on color is carried by something else:

| Component         | Normal                                                          | Forced colors                                    |
| ----------------- | --------------------------------------------------------------- | ------------------------------------------------ | --- | ---------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Button            | `default`, `primary`, and `danger` differ in fill               | A normal, a heavy (4px), and a dashed border     |
| Progress bar      | `default`, `success`, `warning`, and `danger` differ in pattern | The same patterns, in the system highlight color |
| Disabled controls | Flat and desaturated                                            | The system disabled-text color                   |
| Focus             | A two-tone ring                                                 | A 2px `Highlight` outline                        |     | Slot, item stack | Selected is a heavier ring and a darker fill; highlighted is a dotted outline; invalid is a frame and a hatched corner | A 3px `Highlight` outline, a dotted border, and a dashed border |
| Meter             | Solid, diagonally hatched, and cross-hatched fills              | The same patterns, in the system highlight color |
| Status light      | A ring, diamond, circle, triangle, and square                   | The shapes in the system text color              |
| Recipe            | A solid or dashed availability chip; selected is a ring         | A 3px `Highlight` outline when selected          |

Sizes do not change in this mode: a button has the same height with and without forced colors.

## Reduced motion

With `prefers-reduced-motion: reduce`, the loading spinner and the indeterminate stripes stop moving, and a progress or meter fill jumps to its new size instead of growing.

## Status is never color alone

Every state in the inventory has a cue besides color. A meter's state is a fill pattern and a word in its value text ("15%, warning"). A status light's variant is a shape, and its meaning is its text. A recipe that cannot be made says "unavailable". An invalid slot has a frame, a hatched corner, and the word "invalid" in its accessible name. Item durability is a solid, hatched, or cross-hatched bar and a percentage in the accessible name.

## Inventory keyboard model

A slot grid is one tab stop. Tab enters it at the item that last had focus, else the first selected item, else the first enabled one, and a second Tab leaves it. Arrow keys move focus, and moving focus never changes the selection.

| Key                 | Action                                                                          |
| ------------------- | ------------------------------------------------------------------------------- |
| Arrow keys          | Move in reading order and by row; nothing wraps from the last item to the first |
| Home, End           | First and last item of the row                                                  |
| Ctrl+Home, Ctrl+End | First and last item of the grid                                                 |
| Space               | Selects (single) or toggles (multiple); activates when selection is none        |
| Enter               | Activates; never changes the selection                                          |
| Shift+Arrow, Ctrl+A | Extends the selection, or selects all (multiple)                                |

A grid with selection is a `listbox` of `option` items, and with none a `group` of buttons. It is not `role="grid"`, since a wrapping layout has no rows and cells. The automated checks cover this tree in all three engines, but it has not yet been checked by hand with a screen reader.

## Accordion keyboard model

Each enabled accordion heading is its own tab stop, so Tab moves through them like any other buttons. Arrow keys are a shortcut between headings, and they only act while focus is on a heading, so arrows inside an expanded panel (a text field, a slider) are left alone.

| Key          | Action                                                    |
| ------------ | --------------------------------------------------------- |
| Enter, Space | Expand or collapse the item                               |
| Down, Up     | Focus the next or previous enabled heading; nothing wraps |
| Home, End    | Focus the first or last enabled heading                   |

A heading is `role="heading"` with an `aria-level` that the page chooses (`level`, default 3), holding a button with `aria-expanded` and `aria-controls`. The panel is a `region` named by that button. The plus or minus drawn beside the heading says the same thing as `aria-expanded`, so state is not color alone.

## Tabs and toolbar keyboard model

One tab of a tab list, and one item of a toolbar, is the tab stop. Arrow keys move between the others, and nothing wraps. Horizontal arrows swap in right-to-left languages, and vertical tabs use Up and Down. Disabled tabs and items are skipped.

| Key          | Tabs                                                                          | Toolbar                    |
| ------------ | ----------------------------------------------------------------------------- | -------------------------- |
| Left, Right  | Previous and next tab; with automatic activation, also selects it             | Previous and next item     |
| Home, End    | First and last enabled tab; with automatic activation, also selects it        | First and last item        |
| Enter, Space | With manual activation, selects the focused tab                               | Activates the focused item |
| Tab          | To the selected panel if it has something to reach or a `tabindex`, else past | Leaves the toolbar         |

A tab list is `role="tablist"` with `role="tab"` children, `aria-selected`, and `aria-controls`; its panels are `role="tabpanel"` and named by their tab. A toolbar is `role="toolbar"` with the application's `aria-label`. A select, text field, number field, or slider in a toolbar is its own tab stop, since it needs the arrow keys. The selected tab differs from the rest by a bar on the edge facing its panel, as well as a pressed-in surface.

## Windows and dialogs

A modal window or dialog makes the rest of the page inert, traps Tab and Shift+Tab inside, starts focus on the content (never on the close or move button), and gives focus back to what opened it. It also holds the page's scroll while it is open. A click on the backdrop closes nothing.

| Key        | Action                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| Escape     | Closes the topmost overlay if it is dismissible; a `persistent` dialog or non-dismissible window takes it and does nothing |
| Arrow keys | In a window's move mode, move it by 8px, or 32px with Shift                                                                |
| Enter      | In move mode, places the window                                                                                            |
| Escape     | In move mode, puts the window back, and leaves the window open                                                             |

Dragging a window by its titlebar has a single-pointer alternative, the move button (WCAG 2.5.7). Overlays are named by their heading, or by an `aria-label`, and a dialog with `alert` is an `alertdialog` described by its content. A window never leaves the viewport, and a modal window fits it at 375px and at 200% zoom: its body scrolls, and is a focusable region while it does.

## Popovers and menus

A popover's trigger has `aria-expanded`, and `aria-haspopup="menu"` for a menu. Focus moves into a content popover only for a keyboard open; a menu always moves focus to its first enabled item. Whatever closes it, focus that was inside goes back to the trigger.

| Key                | Content popover                                                                              | Menu                                           |
| ------------------ | -------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Enter, Space       | On the trigger: toggles, and moves focus in                                                  | On the trigger: toggles; on an item: activates |
| ArrowDown          | Nothing                                                                                      | On the trigger: opens; on an item: next item   |
| ArrowUp, Home, End | Nothing                                                                                      | Previous, first, and last item; no wrapping    |
| Tab                | Past the last element (Shift+Tab before the first) closes it and carries on from the trigger | Closes it and carries on from the trigger      |
| Escape             | Closes the topmost overlay, and focus goes back to the trigger                               | Same                                           |

Menu items must be focusable and carry `role="menuitem"`, `menuitemcheckbox`, or `menuitemradio`. Inside a modal window or dialog the trigger must be in the same one, since the rest of the page is inert.

## Toasts

A toast stack has two live regions that exist before any toast does: `role="alert"` for `warning` and `danger` toasts, and `role="status"` for `info` and `success` ones. A region added together with its content is not reliably announced, so the regions stay, and the stack moves each toast into the right one. A toast outside a stack is shown but not announced.

A toast never takes focus, and has a dismiss button reachable with Tab. Its countdown pauses while the pointer is over it, while focus is inside it, and while the page is hidden, and it resumes with the time that was left. An `info` or `success` toast closes after 5 seconds; a `warning`, a `danger`, and any toast with an action stay until dismissed. Each variant is a shape as well as a color, and the text is always in the text color.

A modal window or dialog makes everything outside it inert, a toast stack included, so put a stack inside the dialog when its toasts must be usable while it is open. A toast shown behind a modal still counts down.

## Keyboard focus

The focus ring appears on `:focus-visible`, so keyboard users always get one, and it is never removed without a replacement. A tooltip opens when its anchor receives keyboard focus, and Escape closes it without moving focus.

## What is tested

- Reflow: every component, in every theme and density and four content variants, at four widths from 187px to 512px.
- Accessibility: `axe-core` over the same combinations, with no serious or critical violations.
- Appearance: screenshots in Chromium, Firefox, and WebKit at 100% and 200% zoom, in RTL, and in forced colors.
